Exploitation d'un système d'authentification
par invite codes & Padding Oracle Attack

09 Apr 2026 · 8 min read · Tippi RAZAFINDRORIAKA
#crypto #web #rce #aes-cbc #prng #ctf

TL;DR : Deux vulnérabilités enchaînées un générateur de tokens basé sur mt_rand() PHP dont le seed est bruteforçable, puis une Padding Oracle Attack sur AES-CBC — aboutissent à une exécution de commandes arbitraires sur le serveur cible.

Reconnaissance

Un scan de ports complet révèle un serveur Apache/PHP tournant sur un port non standard. L'énumération des répertoires expose plusieurs endpoints intéressants :

  • Une documentation API protégée par mot de passe
  • Un dossier de logs accessible publiquement
  • Un dashboard nécessitant une authentification

Extraction d'informations sensibles

Les fichiers de logs exposés publiquement contiennent des traces d'activité incluant un token d'authentification encodé en base64. Le décodage révèle une valeur numérique correspondant au résultat d'un générateur de nombres pseudo-aléatoires.

Déobfuscation de code JavaScript

Le fichier JavaScript lié à la documentation API utilise une technique d'obfuscation par réordonnancement de tableau avec des index hexadécimaux. L'exécution directe du code dans un environnement Node.js suffit à extraire les valeurs en clair, notamment le mot de passe donnant accès à la documentation API. 

$ node obfuscated.js
# Output : mot de passe en clair récupéré

Reverse engineering de l'algorithme de génération de tokens

La documentation API expose le code source de l'algorithme de génération d'invite codes : 

function calculate_seed_value($email, $constant_value) {
    $email_length = strlen($email);
    $email_hex    = hexdec(substr($email, 0, 8));
    $seed_value   = hexdec($email_length + $constant_value + $email_hex);
    return $seed_value;
}

mt_srand($seed_value);
$random      = mt_rand();
$invite_code = base64_encode($random);

La vulnérabilité réside dans l'utilisation de mt_rand() avec un seed déterministe calculé depuis des paramètres connus (longueur et contenu de l'email). Connaissant un output de mt_rand() depuis les logs, il est possible de retrouver le seed exact par bruteforce, puis d'en déduire la constante secrète utilisée par l'application. Une fois la constante connue, n'importe quel invite code peut être forgé pour n'importe quelle adresse email enregistrée.

mt_rand() est un générateur congruentiel linéaire le même seed produit toujours le même résultat. Il est cryptographiquement inapproprié pour générer des tokens d'authentification.

Padding Oracle Attack sur AES-CBC

Une fois authentifié, le dashboard transmet un paramètre chiffré via l'URL. Lorsqu'une valeur corrompue est soumise, l'application retourne un message d'erreur de padding distinct — condition nécessaire et suffisante pour une Padding Oracle Attack.

En mode CBC (Cipher Block Chaining), le déchiffrement de chaque bloc dépend du bloc chiffré précédent (le vecteur d'initialisation pour le premier bloc). En manipulant ce bloc précédent octet par octet et en observant si le padding est valide, il est possible de déduire les octets intermédiaires, puis de reconstruire le plaintext ou de forger n'importe quel ciphertext. 

# padbuster automatise le déchiffrement
$ padbuster "http://target/dashboard?param=CIPHERTEXT" CIPHERTEXT 8 -encoding 0

# Résultat : le paramètre contient une commande shell
# Plaintext déchiffré : date +%Y

# Forge du ciphertext exécutant une commande arbitraire
$ padbuster "http://target/dashboard?param=CIPHERTEXT" CIPHERTEXT 8 \
    -encoding 0 -plaintext "cat /home/ubuntu/flag.txt"

Le déchiffrement révèle que le paramètre contient une commande shell (date +%Y) exécutée côté serveur. En forgeant le ciphertext correspondant à cat /home/ubuntu/flag.txt, on obtient l'exécution arbitraire de commandes.

Recommandations de remédiation

Génération de tokens

  • Remplacer mt_rand() par random_bytes() ou openssl_random_pseudo_bytes() ces fonctions produisent de l'aléatoire cryptographiquement sûr.
  • Ne jamais exposer l'algorithme de génération dans une documentation publique.

Chiffrement AES-CBC

  • Utiliser un mode authentifié comme AES-GCM qui garantit à la fois la confidentialité et l'intégrité toute modification du ciphertext invalide le message sans révéler d'information sur le padding.
  • Ne jamais exécuter le contenu d'un paramètre déchiffré comme une commande shell.
